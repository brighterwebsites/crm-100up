| 10 | Simulation / auto battery sizing — **inherited from V46** | A system can "survive July" purely by coasting on its starting charge. `simulate()` begins the battery FULL and runs exactly 31 days, so it asks *"does it run flat within one July?"* — not *"is this sustainable?"*. Where the array cannot meet the load, a large enough battery still passes because it never quite empties before the month ends. **Reproduction** (Vanessa, 2026-08-11): 20 kWh/day, 15 fixed panels, roof, auto inverter, auto battery 1–40. Min inverters 1 → Sigenergy passes, Deye fails. Min inverters 21 → both fail. Min inverters 26+ → Sigenergy passes again. **Cause.** 15 × 475 W = 7.125 kW. July averages 2.35 kWh per kW per day here, so production is ~16.7 kWh/day against ~23.6 kWh/day of load plus standby — a ~7 kWh daily deficit, ~217 kWh across the month. The array simply cannot sustain this load at any battery size. Sigenergy "passes" only once its bank exceeds that 217 kWh deficit (40 × 9 = 360 kWh), coasting down from full. Deye tops out at 40 × 5.1 = 204 kWh and so never does. The non-monotonic behaviour in min-inverters is the second half: battery parity rounds units up to a multiple of the floor and steps by it, so a floor of 21 tries only 21 units (189 kWh, fails) while 26 tries 26 (234 kWh, passes). Fewer candidate counts, not better systems. | Two separate decisions, both for Fred. **(a)** Should a pass require sustainability — e.g. end-of-month SOC >= start, or a repeated-July run — rather than merely not hitting zero? Today's answer flatters undersized arrays. **(b)** Should the UI warn when average daily production is below average daily load, since no battery can fix that? Note this is V46 behaviour faithfully ported, so it is NOT a parity-gate divergence — the rebuild matches. Changing it is a product decision, and it would move quoted system sizes. | Open — needs Fred |
